# Reusable project workflows

These procedures can be read directly by either assistant. They do not require a paid plugin or installed skill. The Mindpalace Builder skill routes to the same three kinds of work.

## Implement a Quest WebXR slice

Read the active milestone and current package versions. Confirm the scene uses the existing renderer. If no code exists, scaffold the selected React/Vite stack, not a server-rendered framework. Resolve peer versions from current manifests, install without force flags and retain the lockfile.

Build the smallest end-to-end scene: supported/unsupported capability states, user-initiated immersive entry, a readable spatial cue, controller target selection, origin-based teleport/snap turn, session end and desktop fallback. Keep controller event mapping version-specific; validate against installed types and official examples.

Profile the visible room and asset load path. Keep a named measurement scene. Document active refresh rate, observed frame cadence, asset sizes and what device produced the result. An emulator run can establish wiring, not comfort, optical readability or Quest frame performance. Record the remaining real-device steps without claiming they passed.

## Convert material to mnemonic content

Read the source, selected language profile, allowed asset IDs, chosen room/locus IDs and current schema. Split the material into atomic objectives. Preserve each exact answer and source excerpt. Mark uncertainty; do not turn an illustrative metaphor into a fact.

Retrieve saved hooks from the supplied dictionary. Suggest missing hooks for review, without changing approved ones. Use an optional number peg, a coherent meaning action and an ordered pronunciation chain only where useful. Prefer large distinctive actors to tiny collections of objects. Show long chains in chunks.

Return data in the required contract, never executable code. Resolve assets from the provided catalogue. Use a known placeholder or record a missing-asset issue; do not fabricate URLs or models. Validate IDs, room/locus membership, node references, allowed action names and limits. Present a review preview before committing the import.

## Verify storage, review and free deployment

Start with a representative content fixture. Import it into an isolated test database, place an item, reload, review it and export. Reimport as a copy and confirm relationships. Reject malformed references and oversized input without partial writes. Confirm that content import cannot erase review state. If a backup format exists, verify restoration of binary media and scheduler state.

Use stable event IDs to prevent duplicate review application. Freeze the clock in scheduler tests and serialize date fields explicitly. For sync work, test two authenticated users, RLS on every exposed table, private asset policies, offline outbox retries and a revision conflict. A hidden button is not an authorization boundary.

For deployment, inspect the generated `dist/`, asset sizes, routes and headers. Verify a production HTTPS origin and user-driven `immersive-vr` entry. Keep initial hosting assets-only, without a server script, paid service or private media in the bundle. A deployment action requires authorization in the current task. Test on the headset and keep a recoverable prior deployment.
